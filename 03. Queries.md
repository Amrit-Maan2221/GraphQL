# 1️⃣ What a Query Really Is

In GraphQL:

> A **query is just a read request** — it asks the server: “Give me **exactly this data**, no more, no less.”

Unlike REST where:

```
GET /users/101
GET /users/101/vehicles
```

…GraphQL **lets you do both in one request**, and you choose the exact fields.

---

# 2️⃣ Basic Query Structure

```graphql
query {
  user(id: 101) {
    name
    email
    vehicles {
      plateNumber
    }
  }
}
```

**Breakdown:**

* `query` → optional keyword, denotes read operation
* `user(id: 101)` → field with arguments
* `{ name email vehicles { plateNumber } }` → **selection set**, only what the client wants

---

# 3️⃣ How Queries Map to the Schema

Every field in your query must exist in the **schema**:

```graphql
type User {
  id: ID!
  name: String!
  email: String
  vehicles: [Vehicle]
}
```

GraphQL runtime:

1. Reads your query
2. Validates it against schema
3. Calls **resolvers** for each field
4. Returns **exactly requested fields**

**Senior insight:** The schema + query combo is your **strong contract**. No surprises.

---

# 4️⃣ Nested Queries

GraphQL shines with **nested relationships**:

```graphql
query {
  user(id: 101) {
    name
    vehicles {
      plateNumber
      model
    }
    tickets {
      id
      status
    }
  }
}
```

* Frontend gets all related data in **one request**
* No multiple roundtrips
* Efficient for mobile

---

# 5️⃣ Queries with Arguments

Fields can accept **arguments** (like function parameters):

```graphql
query {
  user(id: 101) {
    name
  }
}

query {
  vehicles(limit: 5, status: "active") {
    plateNumber
  }
}
```

* Arguments are validated by the schema
* Prevents invalid queries
* You can combine multiple filters, pagination, etc.

---

# 6️⃣ Aliases & Multiple Fields

Sometimes you want the **same field with different arguments**:

```graphql
query {
  activeVehicles: vehicles(status: "active") {
    plateNumber
  }
  inactiveVehicles: vehicles(status: "inactive") {
    plateNumber
  }
}
```

* `activeVehicles` and `inactiveVehicles` → **aliases**
* Avoids collisions in the response

---

# 7️⃣ Variables — Cleaner Queries

Never hardcode arguments in real apps:

```graphql
query GetUser($id: ID!) {
  user(id: $id) {
    name
    email
  }
}
```

Variables:

```json
{
  "id": 101
}
```

✅ Cleaner, reusable, and safe

---

# 8️⃣ Senior Tip: Query Execution Internals

When you send a query:

1. GraphQL parses it into an **Abstract Syntax Tree (AST)**
2. Validates against the **schema**
3. Executes resolvers **depth-first** for each requested field
4. Combines results into **exact JSON**

* This is why GraphQL can batch and avoid N+1 queries if you implement resolvers correctly.

---

# ⚡ TL;DR – Queries

* Queries = **read operations**
* Selection set = **exact fields client wants**
* Arguments = **parameters**
* Nested fields = **relationships traversed in one request**
* Variables = **dynamic and reusable queries**
* Aliases = **avoid field name conflicts**
* Schema = **contract & validation**
* Backend = **resolver execution**
