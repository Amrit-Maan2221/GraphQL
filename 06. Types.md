# 1️⃣ Two Main Categories

GraphQL types are broadly:

1. **Scalar Types** – the basic building blocks
2. **Object / Complex Types** – structured, connected data

---

# 2️⃣ Scalar Types (Primitive)

GraphQL has **built-in scalar types**:

| Type      | Description                             |
| --------- | --------------------------------------- |
| `Int`     | 32-bit integer                          |
| `Float`   | Floating-point number                   |
| `String`  | UTF-8 string                            |
| `Boolean` | true / false                            |
| `ID`      | Unique identifier, serialized as string |

**Senior insight:**

* `ID` is not a number — treat it as a string for caching / frontend
* Scalars are **leaf nodes in your query**, they don’t have child fields

---

# 3️⃣ Object Types

* Define **structured data with multiple fields**
* Can reference other types → forms the **graph**

Example:

```graphql
type User {
  id: ID!
  name: String!
  vehicles: [Vehicle]
}

type Vehicle {
  plateNumber: String!
  model: String
}
```

* `vehicles: [Vehicle]` → links User → Vehicle
* Object types = where **nested queries** happen

---

# 4️⃣ Input Types

* Special type used **only as arguments** in mutations (or queries)
* Structured, strongly typed, helps validation

```graphql
input CreateUserInput {
  name: String!
  email: String!
}
```

* Used in mutation:

```graphql
mutation {
  createUser(input: { name: "Amrit", email: "a@example.com" }) {
    id
    name
  }
}
```

**Senior insight:**

* Input types = your **API contract for writes**
* Always use input objects instead of long argument lists

---

# 5️⃣ Enum Types

* Restrict a field to **specific set of values**

```graphql
enum VehicleStatus {
  ACTIVE
  INACTIVE
  SOLD
}
```

* Use in type:

```graphql
type Vehicle {
  plateNumber: String!
  status: VehicleStatus!
}
```

**Senior insight:**

* Enums improve **validation & self-documentation**
* Prevents invalid states in DB

---

# 6️⃣ Interface Types

* Abstract type: defines **common fields**, multiple types can implement it

```graphql
interface Person {
  id: ID!
  name: String!
}

type Customer implements Person {
  id: ID!
  name: String!
  loyaltyPoints: Int
}

type Employee implements Person {
  id: ID!
  name: String!
  department: String
}
```

* Queries can return `Person`, resolver decides concrete type

**Senior insight:**

* Useful for **polymorphism** in schema
* Helps frontend handle multiple types with shared fields

---

# 7️⃣ Union Types

* Like interface but **no shared fields required**

```graphql
union SearchResult = User | Vehicle | Ticket
```

* Query returns **any of these types**, frontend checks actual type
* Resolver must return type info

**Senior insight:**

* Use when you want **flexible return types**
* Avoid if fields overlap → prefer interfaces

---

# 8️⃣ List & Non-Null Modifiers

* `[Type]` → list of items
* `Type!` → non-nullable

```graphql
type User {
  id: ID!
  vehicles: [Vehicle!]!   # list cannot be null, items cannot be null
}
```

**Senior insight:**

* Always think about **nullability** carefully
* Avoid `[Type]!` with nullable items if your DB never returns null → avoids runtime errors

---

# 9️⃣ Summary Table – All GraphQL Types

| Category        | Examples                                  | Purpose                                          |
| --------------- | ----------------------------------------- | ------------------------------------------------ |
| Scalars         | `Int`, `Float`, `String`, `Boolean`, `ID` | Leaf nodes, primitive data                       |
| Object          | `User`, `Vehicle`                         | Structured data, can have nested fields          |
| Input           | `CreateUserInput`                         | Arguments for mutations or queries               |
| Enum            | `VehicleStatus`                           | Restrict to predefined values                    |
| Interface       | `Person`                                  | Abstract shared fields, multiple implementations |
| Union           | `SearchResult`                            | Flexible return types without shared fields      |
| List & Non-Null | `[Type]`, `Type!`                         | Control collections and nullability              |
